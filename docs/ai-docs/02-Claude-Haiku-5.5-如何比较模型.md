# Claude Haiku 5.5：程序员应该怎样比较 AI 模型

原文：[Claude Haiku 5.5](https://simonwillison.net/2026/Oct/7/claude-haiku-5-5/)｜Simon Willison，2026 年 10 月 7 日。

## 先用一句话理解

这篇不是单纯的新模型新闻。Simon 把模型**标价、输入长度、token 计算方式、实际测试效果和套餐额度**放在一起看，示范了程序员选择模型时应该问哪些问题。

## 先认识「模型价格」

调用模型 API 时，常见计价单位是 token。你可以粗略把 token 理解成模型读写文本时使用的小片段；它不等于一个汉字或一个英文单词。一般分别计算：

- **输入 token**：你发给模型的内容，包括提示词、资料、代码和聊天历史。
- **输出 token**：模型返回的回答，有时还包括推理相关的计费内容，具体以服务商说明为准。

因此，「每百万 token 多少钱」只是单价。一次任务的实际费用还取决于输入有多长、输出有多长、是否重复调用，以及模型如何把你的内容切成 token。

## 作者怎样分析 Haiku 5.5

文章发表时，Simon 把 Haiku 5.5 与其他低价模型进行比较。他特别指出两件容易漏看的事：

1. **输入超过一定长度后，单价可能变化。** 对一个小提示词便宜的模型，不一定适合把一整个大型代码仓库塞进去。
2. **tokenizer 会影响真实用量。** tokenizer 是把输入转换成 token 的规则。Simon 用自己的计数工具测试，发现同一份长提示词在新旧 Haiku 上统计出的 token 数不同。因此，即便表面的单价下降，真实账单也要按具体输入测算。

文中的价格、阈值和订阅额度都是 2026 年 10 月 7 日的产品快照；它们不是永久有效的购买建议。

## 为什么作者让模型画「骑自行车的鹈鹕」

Simon 经常使用同一个图像或 SVG 生成任务，观察不同模型的输出。他在这篇文章中用自己的 `llm` 命令行工具调用 Haiku 5.5，并比较不同推理力度下的结果、耗时和费用。

这个做法有价值：固定题目能让你直观看到一个模型版本的变化。但也要注意，**一张画不能代表它在写代码、查资料或处理中文时的整体能力**。作者还提到模型可能已经知道这类测试题，因此补做了另一个不同题目的比较。对程序员来说，最可靠的测试题应来自你自己的实际工作。

## 用你的任务来比较模型

假设你要用模型修一个 Python bug。可以准备同一个输入，让候选模型都做：

> 给定报错、相关函数和一个失败用例，请先解释根因，再给最小修改，并说明如何验证。

然后记录四项：

| 指标 | 要看什么 |
| --- | --- |
| 正确性 | 测试是否通过？有没有改坏其他行为？ |
| 可审查性 | 解释是否清楚？改动是否过大？ |
| 时间 | 从发送请求到拿到可用结果要多久？ |
| 总费用 | 完成任务一共用了多少输入、输出 token 和重试次数？ |

这里的「总费用」比单次调用单价更有意义：便宜模型若需要反复重试，最后可能并不便宜。反过来，强模型若一次解决，也未必更贵。

## 套餐额度是什么

文章还介绍了 Anthropic 当时为部分订阅方案提供 API 额度，以及余额用尽后停止请求等计费控制。这里要分清两种东西：**聊天产品的订阅权限**与**开发者 API 的计费或赠送额度**。它们是否互通，取决于平台当前政策。做项目时应查看自己账户的实际账单和额度页面。

## 20 分钟练习

选一件你本周真要做的小任务，例如「解释一段不熟悉的代码」。写下你的验收标准，再让两个模型或同一模型的两个配置处理完全相同的输入。不要只比较回答是否流畅；检查它引用的代码行是否正确、建议能否运行、你需要补充几轮说明。这样你就在做一个简单的模型评测，而不只是看排行榜。
