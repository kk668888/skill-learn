## 1. 它解决什么问题

它对付两种**缓慢发生的资产流失**，这两种流失都极难在当下被察觉：

**其一，术语漂移。** 一个概念在项目里逐渐长出多个名字——`account` / `customer` / `user` 被混着用，或者同一个词在不同上下文里指不同的东西。这不只是措辞问题：**当两个人（或人和 AI）用同一个词表达不同概念时，讨论会在互相误解中推进很久才被发现**，而发现时已经浪费了大量时间。更糟的是，这种歧义通常是在一次追问里被临时澄清的（"你说的 account 是指付费方还是登录账号？"），然后**随着对话结束而消失**——下次再讨论，同样的歧义重新出现。

**其二，决策理由的遗忘。** 代码和文档通常记录"用了什么方案"，但不记录"为什么没用另一个"。半年后有人（很可能是你自己）看到一处奇怪的设计，无从判断它是刻意权衡的结果还是历史遗留的 bug，于是要么不敢动，要么贸然改掉。

**设计立场**：这两种流失对应**两种不同的资产**，因此需要**两个不同的容器**——

| 资产 | 特征 | 容器 |
|------|------|------|
| 术语 | 高频、轻量、易变 | `CONTEXT.md` 术语表 |
| 决策理由 | 低频、重量、持久 | `docs/adr/` 决策记录 |

> 技能原文对这个立场有一句很精确的自我界定：它是 **active** 纪律（改模型），不是任何技能都能顺手做的 **passive** 习惯（读模型）。这句话是整套纪律的锚——它决定了这个技能**什么时候该触发、什么时候不该**。

## 2. 核心设计决策

### 决策一：拆成两个容器，且职责不许混

**选了什么**：术语进 `CONTEXT.md`，取舍进 ADR，**两个文件的职责有严格边界**。

**为什么**：两者的**读写模式完全不同**。

- 术语表是**高频、双向**的：讨论中随时查、随时改，条目短、数量多。
- ADR 是**低频、单向**的：写一次、几乎不改，条目长、数量少。

如果把两者塞进一个文件，会同时破坏两边——术语表被长文淹没而不再可扫，ADR 被高频改动稀释而失去"记录"的严肃性。

**原文里最硬的一条约束**是配套的：`CONTEXT.md` 应当"**完全不包含**实现细节……它是术语表，仅此而已"。**为什么这么严**——因为它防的是**范围蔓延**：术语表一旦开始收纳决策、计划、实现细节，就变成没人读的杂物间。而一个没人读的术语表，比没有术语表更糟——它会被引用，但内容已经不可信。

### 决策二：惰性创建

**选了什么**：只在你确实有东西要写的时候才建文件。没有术语就不建 `CONTEXT.md`，没有 ADR 就不建 `docs/adr/`。

**为什么**：反脚手架。预先建好空的 `CONTEXT.md`，会制造一种"这项工作已经开始"的错觉，而实际上里面什么都没有。

更深一层的理由是：**文件的存在本身就是一个信号**——"这里有真东西"。这个信号有价值，不该被空壳稀释。当一个项目里存在 `CONTEXT.md` 时，你（和 AI）会自然地认为它记录了被敲定的词汇；如果它经常是空的，这个信号就废了。

### 决策三：即时落盘，不许攒批

**选了什么**：术语被敲定时**当场**更新 `CONTEXT.md`。原文措辞是 `Don't batch these up`。

**为什么**：**语境是易逝的**。术语之所以在那句话里被澄清，是因为当时正在讨论一个具体的边界情况；拖到会话末尾再写，你已经丢失了那个语境，只能写出一个四平八稳、失去了边界的通用定义——而**失去边界的定义往往就是没用的定义**。

**代价**：打断当前讨论的连贯性。你正在往下推进，AI 却停下来写文件。这个代价在 `grill-with-docs` 里尤其明显（见该技能的失效分析）。

### 决策四：ADR 三判据——用"过滤器"而不是"清单"思维

**选了什么**：只有**同时**满足三条才提议 ADR：① 难以逆转；② 脱离上下文会令人意外；③ 是真实取舍的产物。

**为什么**：这个决策的重点在**逻辑形式**，而不在三条具体内容。三种可能的写法：

- *清单式*（"值得记录的决策包括：架构选型、技术栈选择、数据模型设计……"）—— 问题是不可能穷举，且每条都可以被解释成"符合"。
- *数量配额*（"每个迭代不超过 N 条 ADR"）—— 与重要性无关。
- *过滤器式*（三条必须**同时**成立）—— **用"与"逻辑强制收敛**。

选过滤器是因为它有一个清单式没有的性质：**它筛掉的决定远多于它保留的**。三条里缺任何一条就跳过——这个偏严的设定是刻意的，因为：

> **ADR 一旦膨胀，就没人读了；而没人读的决策记录等于不存在。**

逐条看，判据筛掉的分别是：

| 判据 | 筛掉的是 | 理由 |
|------|---------|------|
| 难以逆转 | 容易反悔的决定 | 改主意成本低，不值得留档 |
| 脱离上下文会意外 | 不言自明的决定 | 没有"为什么"需要解释 |
| 是真实取舍 | 没有替代方案的决定 | 无取舍可讲 |

**代价**：边界情况会被误判。"这个决定算不算难逆转"是主观判断，而且执行判据的是 AI——它可能手软，把本该跳过的东西写成 ADR。

### 决策五：主动挑战用户

**选了什么**：五条具体手段——对照术语表质疑、磨尖模糊语言、编造边界场景、与代码交叉验证、就地更新。

**为什么**：这五条不是随手列的，它们**方向各异**，共同构成一套"进攻"：

| 手段 | 方向 | 作用 |
|------|------|------|
| 对照术语表质疑 | 往后看 | 用**既有定义**约束当下表达 |
| 磨尖模糊语言 | 往内收 | 挤压同义词空间，一个概念一个词 |
| 编造边界场景 | 往外推 | 用极端情况探索概念边界 |
| 与代码交叉验证 | 往下扎 | 用**客观事实**反击口头陈述 |

**共同点是不接受"大概是这样"**。

其中"与代码交叉验证"值得单独看：它把**代码当作领域模型的第一手证据**。用户的描述可能过时、可能只是他的期望，而代码是实际发生的事。两者矛盾时，原文的处理方式很关键——**不预设谁对，而是把矛盾本身交还给用户裁决**（"哪个才是对的？"）。这个姿态避免了一个常见错误：AI 擅自认定"代码是对的，你的描述过时了"。

### 决策六：把格式外置到附属文件

**选了什么**：正文只说"用 `CONTEXT-FORMAT.md` 里的格式"、"用 `ADR-FORMAT.md` 里的格式"，而不内联格式细节。

**为什么**：又一次 Progressive Disclosure——正文只讲**什么时候写、为什么写**（需要每次都在场的判断依据），格式细节只在真正动笔时载入。这让主文件保持在"方法论"层面，不被格式细节稀释。

**代价**：多两个文件要跟着走。`install-skills.mjs` 复制的是整个技能目录（含附属文件），所以安装时不会漏；但如果手工只拷 `SKILL.md`，格式文件就丢了。

## 3. 机制如何运转

```
讨论进行中
   ↓
感知到某个术语被使用
   ├─ 与 CONTEXT.md 中既有定义冲突？ → 当场指出，要求二选一
   ├─ 含糊 / 一词多义？            → 提出精确的规范术语
   ├─ 涉及概念边界？               → 编造极端场景压测
   └─ 涉及"如何工作"？             → 核对代码，矛盾则摆出来
   ↓
术语被敲定 → 立刻写入 CONTEXT.md（不攒批）
   ↓
出现难以逆转的取舍？
   └─ 三判据全过？ → 提议建 ADR；缺一 → 跳过
```

关键约束：**"立刻写入"这一步是最容易被违反的**。它的时间窗口很窄（语境新鲜的那几分钟），而违反的后果不会立刻显现——你只会在几周后拿到一份失去了边界的、没用的定义。

## 4. 什么时候会失效

| 场景 | 后果 | 原因 |
|------|------|------|
| `CONTEXT.md` **被塞进非术语内容** | 变成杂物间，没人再读；被引用但不可信 | 决策一的范围保护依赖执行者克制，没有强制机制 |
| **ADR 判据执行手软** | ADR 膨胀，没人读，决策记录形同废除 | 三判据是主观判断，AI 倾向于"都记下来更保险" |
| **你敷衍 AI 的质疑** | 术语表保留模糊定义，或保留你的旧用词 | 五条手段全部依赖你**真的回答**那些挑战 |
| 项目**没有代码** | "与代码交叉验证"失效，四路进攻少一路 | 该手段以代码为客观锚点，纯文档/构思项目没有 |
| 术语**只在写时被想起** | 该查的时候没人查，歧义照旧 | 技能规定了"怎么维护"，无法强制"何时查阅" |
| 多上下文仓库**判断错结构** | 术语写到了错误的 `CONTEXT.md` | 单上下文 vs `CONTEXT-MAP.md` 的判定由 AI 做，可能误判 |
| 项目**已有既成词汇表** | 与既有术语冲突，或产生两套并行 | 该技能假设术语表由本纪律维护，没有"与外部协商"的机制 |

> **最值得注意的是第一条。** `CONTEXT.md` 的"只是术语表"约束**没有任何机制保障**——它完全依赖执行者（人和 AI）在每次想往里写点别的什么时，自己克制住。这是一个**靠自律维持的边界**，而自律在长期中总会松动。反过来看，原文把这条写得如此绝对（"nothing else"，"totally devoid of"），正是因为它知道自己在依赖自律，只能用最不容辩解的措辞来加固。

## 5. 与其他技能的协作

| 关系 | 说明 |
|------|------|
| **被** `grill-with-docs` **调用** | 作为落盘内核，与 `grilling` 组合；这是它最主要的入口 |
| **独立可用** | 允许自动触发，改 `CONTEXT.md` 或写 ADR 时可单独唤起，不必捆绑拷问 |
| 与 `grilling` 的张力 | 一个要"批量连贯推进"，一个要"随时叫停落盘"——节奏相反但目标互补 |
| 与 Superpowers / OpenSpec 的同构 | 三者都在对抗"对话易逝"，都选择把共识落成磁盘文件。`CONTEXT.md` ≈ OpenSpec 的 `specs/`，`ADR` ≈ OpenSpec 的归档决策 |
