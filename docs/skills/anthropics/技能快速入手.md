# skill-creator 技能快速入手

## 适用场景

你有一项会反复交给 AI 做的工作，想把做法写成可复用的技能。第一次练习只完成**意图确认、技能草稿和测试提示词**；评估与迭代留到下一次。这里以“把会议纪要整理为行动项”为例。

## 准备条件

- 在支持加载 `skill-creator` 的 AI 编码工具中打开一个**练习项目**；新技能的文件只写在该项目中，不写进本仓库的 `docs/skills/`。
- 准备一小段可公开使用的虚构会议纪要，包含负责人、期限和一条信息不全的任务。不要用真实会议中的隐私数据。
- 确认自己希望输出什么：本例要求行动项列表，并把缺少负责人或期限的项目明确标为“待确认”。

## 示例输入

在练习项目的对话中发送：

> 请使用 `skill-creator`，帮我创建一个“会议纪要转行动项”技能。输入是一段中文会议纪要；输出是“任务、负责人、期限、待确认信息”四列。不要猜缺失字段。先和我确认触发场景、输入输出及边界；确认后在练习项目中写技能草稿，并给出 2～3 条测试提示词。本次先不运行评估。

## 跟做步骤

1. **确认意图。** 回答助手关于“何时触发、输出格式、缺失信息、是否做测试”的问题。若它把“待确认”改成自动推测，明确纠正。**可观察结果：**双方能用一句话复述技能的用途，且触发场景与四列输出已确定。
2. **人工停点：批准草稿范围。** 在需求未对齐前，不让助手直接创建技能文件。确认后请它把草稿写到练习项目的一个独立技能目录。**可观察结果：**目录内有 `SKILL.md`，文件以 `name` 和 `description` 的 frontmatter 开头，正文说明输入、转换规则和缺失字段的处理。
3. **检查首次产物。** 打开草稿，核对 `description` 是否说明“做什么、何时用”，正文是否禁止猜测缺失字段；再查看 2～3 条测试提示词是否覆盖“字段齐全”和“字段缺失”两种情况。**可观察结果：**你可以指出每条测试输入预期检验的规则。
4. **决定是否继续评估。** 草稿可读不等于技能已可靠。若要正式使用，下一轮让 `skill-creator` 用测试提示词运行、展示结果，依据你的反馈修改并重测。本教程到草稿检查为止。**可观察结果：**你已明确记录“尚未评估”，不会把草稿当成经过验证的技能。

## 完成判断

练习项目中出现可读的 `SKILL.md` 草稿；你已确认其触发条件、四列输出和“缺失信息待确认”规则，并拿到能检验这些规则的测试提示词。若只有一段聊天建议、没有草稿文件，就还没有走完本例。
