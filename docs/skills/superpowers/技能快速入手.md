# Superpowers 技能快速入手

## 适用场景

你准备给已有项目加一个小功能，希望先把需求和设计谈清楚，再写实现计划。本例为**练习用的命令行待办程序增加“只列出已完成任务”的选项**。第一次练习到设计文档经你审查为止，不写功能代码。

## 准备条件

- 在支持 Superpowers 技能的工具中打开一个**独立的 Git 练习仓库**；其中已有可运行的待办程序和列出任务的命令。技能可能写入并提交设计文档，不要用有未整理修改的正式项目练习。
- 准备说明现有命令怎样列任务、完成状态由哪里表示，以及你希望新选项解决什么问题。能从仓库查到的现状可交给助手读取。
- 本例是非视觉的命令行功能；若改练视觉界面，`brainstorming` 可能先单独询问是否使用可视化辅助。

## 示例输入

在练习仓库里发送：

> 请使用 `brainstorming` 技能，为现有待办程序设计“只列出已完成任务”的命令选项。先检查仓库和当前列出任务的行为，一次只问我一个问题；提出不同方案与取舍，分段给我审查设计。现在先不要写应用代码。

## 跟做步骤

1. **查现状、回答单个问题。** 助手先读项目文件，再一次问一个问题，例如选项应怎样与现有筛选组合。**可观察结果：**问题建立在真实命令行为上；你不用解释助手本可从代码读出的事实。
2. **比较方案。** 对助手给出的 2～3 种方案检查取舍，例如新命令、现有命令的参数、或交互式筛选。**人工停点：**明确选定你接受的做法；若方案忽略当前命令约定，让助手重新对照项目。**可观察结果：**选择理由和放弃的方案都说得清。
3. **逐段批准设计。** 助手应说明用户输入、输出、边界情形及验证办法，并逐段征求你的意见。在你批准完整设计前，`<HARD-GATE>` 禁止它写功能代码或调用实现技能。**可观察结果：**最终设计能说明空结果、无效参数及与既有选项的关系。
4. **审查落盘结果。** 设计获批后，技能会把文档写入练习仓库的 `docs/superpowers/specs/YYYY-MM-DD-<主题>-design.md`，自查占位符、矛盾、歧义和范围，并按其规则提交。打开文件亲自审阅；不满意就要求修改，满意再明确确认。**可观察结果：**仓库中有可阅读的设计文件，内容与你批准的方案一致。

## 完成判断

你已经确认了设计文档，能说明新选项的行为和边界，并能从文件中找到这些决定。此时下一步入口是 `writing-plans`：它会把已批准设计拆成实现任务；本例不继续写功能代码。
