# impeccable 技能快速入手

## 适用场景

一个界面已能完成用户任务，但发布前还想系统检查布局、状态和交互，并修复发现的问题。本例对**练习项目中已有的任务列表页**执行一次 `polish`；它是保留当前设计方向的精修，不是重新设计。

## 准备条件

- 准备可运行的练习网站，找到任务列表页的**真实源码路径**和浏览器路由。页面至少有一条任务、空列表状态和一个可操作按钮。操作会修改该练习项目中的界面文件。
- 在支持 `impeccable` 技能的工具中打开该项目；若项目有 `DESIGN.md`、`PRODUCT.md` 或相邻页面，也一并提供给助手。
- 先自己走一遍列表的主要任务，记下最明显的问题，例如窄屏按钮被遮挡。这个观察是示例的起点，实际修复仍要以检查结果为准。

## 跟做步骤

1. **加载页面背景。** 助手应在项目根目录按技能要求运行一次 `impeccable context`，读取 `polish` 手册，核对既有设计约定并查看目标页面。Windows 无 `sh` 时，源码要求改用 `impeccable.cmd`。**可观察结果：**它能指出真实目标文件、现有设计体系和页面的主要操作路径；若启动器不可用，应明确告知并改读现有背景文件。
2. **人工停点：核对精修边界。** 查看它提出的问题清单。若问题需要重做页面概念或改写事实文案，先单独决定是否扩大范围；不要把重设计藏在 `polish` 中。**可观察结果：**保留与修复的部分分别说清楚。
3. **集中修复。** 助手按优先级先处理阻断操作、状态或无障碍问题，再处理布局与视觉不一致。**可观察结果：**练习页面上能看到具体修复，例如窄屏操作不再被遮挡、键盘焦点可见、空状态能说明下一步。
4. **做有限轮验证。** 在桌面和手机宽度下走完整条任务路径，检查鼠标、键盘及适用状态；把一次检查中发现的问题集中修复，最多再确认一轮。**可观察结果：**交付说明列出改动、实际检查过的页面状态及仍未解决的问题，不以“检测无告警”代替人工查看。

## 完成判断

你能在练习页面上复现原问题、看到修复，并在桌面和手机宽度下完成主要操作；视觉身份、事实文案和范围外流程没有被替换。若只是收到一份诊断报告、页面没有改动，本例还未完成 `polish`。
