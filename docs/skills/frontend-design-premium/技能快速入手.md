# frontend-design-premium 技能快速入手

## 适用场景

你要修改一个已有应用页面，希望新交互同时符合项目视觉、可访问性和跨页面行为。本例只给**任务列表的现有搜索框增加清除按钮**：有查询词时可见，清除后立即恢复列表，并把焦点还给搜索框。这是产品页面，属于该技能的完整应用界面路径。

## 准备条件

- 用一个可启动的**练习应用**，其中已有任务列表、可工作的搜索框和至少几条演示数据；先记下页面路由或源码路径，并能在浏览器中打开它。操作会改动练习项目的界面文件。
- 确认工具同时安装了 `frontend-design` 与 `frontend-design-premium`。后者要求**先加载前者**；缺少上游技能时应停下安装，而不是让 AI 凭印象代替。
- 若项目已有 `DESIGN.md`、组件规范或相邻页面，保留它们供助手核对。练习不涉及权限、付款或隐私等高风险决定。

## 示例输入

在练习应用的项目根目录与助手对话：

> 请同时使用 `frontend-design` 和 `frontend-design-premium`。在现有任务列表页的搜索框中增加一个清除按钮：仅在输入非空时显示；点击或键盘激活后立即清空查询、恢复完整列表，并把焦点留在输入框。沿用项目现有视觉与共享组件。先检查页面和相邻交互，再实现并在浏览器验证键盘操作及窄屏布局。

## 跟做步骤

1. **确认页面归类与依据。** 让助手先加载上游技能，再按 premium 规则把目标归为产品页面；读取现有产品背景、`DESIGN.md`、搜索实现和相邻页面。**可观察结果：**它能指出清除按钮应复用的组件或交互模式，以及搜索状态由哪里维护。若关键业务规则相互冲突，在此停下处理。
2. **人工停点：确认行为边界。** 核对“清空后恢复全部任务”“焦点返回输入框”与你想要的一致，再允许编辑。**可观察结果：**变更范围明确为搜索交互及必要的共享实现，不会顺手改掉列表的其他行为或视觉体系。
3. **完成页面改动。** 在非空查询时输入框内或紧邻处出现清除按钮；空查询时隐藏。**可观察结果：**按钮有可理解的名称、可见焦点，鼠标点击和键盘激活都能清空输入；列表马上回到未筛选状态，旧搜索响应不会重新覆盖结果。
4. **按技能要求验证。** 让助手执行项目已有的构建或测试、premium 的检查清单，并在浏览器实际操作：输入、清除、再次输入、键盘 Tab/Enter、窄屏。**可观察结果：**按钮及搜索框在这些状态下稳定可用；报告应列出实际跑过的检查和任何未能验证的项目，而不是笼统声称“已通过”。

## 完成判断

在练习应用中，搜索词非空时能看到并操作清除按钮；清除后输入为空、完整列表恢复、键盘焦点回到搜索框，窄屏没有遮挡。还能指出这次改动遵循了哪个现有视觉或共享交互约定。
