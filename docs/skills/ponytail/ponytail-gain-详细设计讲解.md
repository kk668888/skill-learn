## 1. 它解决什么问题

「ponytail 给我省了多少？」是所有行为类技能都会遇到的收益追问，而它是一个**反事实问题**：要回答它，需要知道「没有 ponytail 时你会写多少代码」——那个版本从来没被写出来，基线不存在。

LLM 面对不可计算的问题时的默认行为是**编一个合理的数字**。「大概省了 40% 吧」听起来专业、具体、无害，但它是虚构。一旦用户拿这个数字去做决策（要不要推广这套技能、省了多少人力），虚构就变成了事故。

同时还有一个工程层面的问题：展示类需求若走通用编码流程，会触发不必要的仓库分析甚至写文件的冲动。

> **设计立场**：它假设「展示与事实必须严格分离」——可以复述测量值，不可以推算未测量值。这个立场决定了它是六技能里唯一**一个仓库数字都不算**的技能。

## 2. 核心设计决策

### 决策一：只复述公开基准，来源钉死

**选了什么**：记分板数字全部来自一段写明的测量（39 任务 × 5 次、Opus 5.5、无技能对照、18 个任务带隐藏检查、几何平均聚合），来源指向 `benchmarks/results/` 与 README。

**为什么**：可溯源是「测量值」与「编造值」的唯一区别。把任务构成和聚合方法写进技能正文，等于给每个数字配了出生证明；用户质疑时，争议落在基准方法论上（可讨论），而不是落在「这数字哪来的」（无法讨论）。

**代价**：数字被硬编码进技能文本，版本演进时需要手工同步，否则展示的是过期基准。

### 决策二：诚实边界——禁止按仓库折算

**选了什么**：绝不输出「你在这里省了 X 行/token」；理由写明（未写出的版本不存在，没有可相减的基线）；把按仓库的真实数字指向 `/ponytail-debt`。

**为什么**：这是对反事实诱惑的**结构性防御**。光说「不要编数字」挡不住模型的即兴发挥；把「为什么算不出来」写成不可满足的前提（基线不存在），再给一条合法出路（debt 的台账是数出来的），模型才有地方安放用户的真实需求。指向 debt 还有个隐含好处：真实数字只可能来自 counted ledger（逐条数出来的账），口径天然保守。

**备选方案**：现场用模型估算「这个任务通常会写多少行」来当基线。**被否决的原因**：估算本身就是编造，还披着「现场测量」的外衣，比直接复述基准更有误导性。

**代价**：用户「我这仓库到底省了多少」的追问得不到直接回答，只有一条指向间接来源的指路。

### 决策三：one-shot 纯展示

**选了什么**：不改变模式、不写标记文件、不持久化任何东西。

**为什么**：展示技能一旦产生副作用（比如顺手「帮你打开 ponytail 模式」），就与 help/gain 的只读契约冲突，用户也无法再信任它的输出是「只是展示」。与 ponytail-help 完全一致的边界措辞，让两个展示技能可以安全地被自动触发。

**代价**：几乎没有——这是全家约束最少的技能。

### 决策四：ASCII 记分板

**选了什么**：纯文本条形图，条长表示相对无技能基线的份额，精确数字写在标签上。

**为什么**：终端环境的最大公约数；相对基线的条形让「▼ 53%」这类削减一目了然；数字入标签保证条形只是示意、事实在文本。

**代价**：无颜色、不可交互；对盲文/读屏场景不如纯文字列表友好。

## 3. 机制如何运转

```
/ponytail-gain 触发
   ↓
不改模式 / 不写文件 / 不分析仓库
   ↓
渲染记分板：
  数字全部来自写明的基准（39×5、几何平均、无技能对照）
  条长 = 相对基线份额；标签 = 精确数字
   ↓
诚实边界检查：
  用户要按仓库折算？→ 拒绝推算，指向 /ponytail-debt
   ↓
结束（状态零变化）
```

这个技能没有复杂机制，它的设计密度全在**边界**上：哪些数字可以说（基准）、哪些不可以说（折算）、说了会怎样（事故）。机制是平凡的，边界是要害。

## 4. 什么时候会失效

| 场景 | 后果 | 原因 |
|------|------|------|
| ponytail 版本演进、基准未同步 | 展示过期数字，收益被高估或低估 | 数字硬编码在技能文本里，没有自动更新机制 |
| 用户把基准当本仓库承诺 | 期望落空，「说好省 53% 呢」 | 边界声明依赖用户读到并接受「平均值 ≠ 你的仓库」 |
| 基准方法论本身有偏 | 记分板忠实展示了有偏的数字 | 技能只复述测量，不负责测量质量；任务集选择偏差在展示层无解 |
| 跨模型/跨工具对比 | 数字不可比（基准只在 Opus 5.5 + Claude Code 上测的） | 测量环境写明了，但快速浏览记分板的用户未必注意 |
| 用户坚持要本仓库数字 | 只能拿到 debt 台账的间接答案 | 反事实基线在结构上不存在，任何折算都是编造 |

## 5. 与其他技能的协作

| 关系 | 说明 |
|------|------|
| 指向 ponytail-debt | 诚实边界的合法出口：唯一真实的按仓库数字来自 debt 的计数台账 |
| 指向 ponytail-audit | 记分板末行把「还能删什么」导向 audit，展示转化为行动 |
| 与 ponytail-help 同构 | 同为 one-shot 纯展示技能，边界措辞一致，可安全自动触发 |
| 服务于 ponytail 主技能 | 回答「为什么要用这套纪律」的收益追问，是全家的对外口径 |
