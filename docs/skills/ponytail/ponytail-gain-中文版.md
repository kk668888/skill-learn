## 正文

被调用时展示这张记分板。一次性执行：不要改变模式、不要写标记文件、不要持久化任何东西。

这些数字是 Ponytail 5 公布的 agent 基准测试结果：无头 Claude Code（Opus 5.5，默认档）在 39 个任务上（真实 FastAPI + React 仓库的功能票、bug 修复、安全与隐私案例、小应用），每个任务跑 5 次，对照组是同一个不带技能的 agent。其中 18 个任务带有正确性与安全性的隐藏检查。每个数字都是各任务中位数的几何平均。它们是**测量值**，不是从当前仓库算出来的。来源：`benchmarks/results/2026-10-07-agentic.md` 与 README。

> **批注**：开篇先把数据来源钉死——任务构成、跑次、对照设置、聚合方式（几何平均）全部交代。这是为了和「编造统计」划清界限：后面所有数字都可溯源到一段写明的测量方法。

## 诚实边界

这些是基准测试的平均值，不是你这个仓库的数字。**绝不**输出按仓库折算的收益数字（「你在这里省了 X 行/token」）：未写出的那个版本从来不存在，实时仓库里没有可以相减的真实基线。唯一真实的按仓库数字来自 `/ponytail-debt`（一份数出来的台账），这张卡指向它，而不是编造一个。

> **批注**：这条边界是整个技能的灵魂，也是对 LLM 一类顽固故障的防御：面对「给我省了多少」这类**反事实问题**，模型的天然冲动是现场编一个听起来合理的数字。把「为什么不能算」写成硬规则（基线不存在，无可相减），比要求「诚实」有效得多。
