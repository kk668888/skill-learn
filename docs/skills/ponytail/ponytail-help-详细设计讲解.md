## 1. 它解决什么问题

ponytail 一家有六个技能、三档强度、一套配置解析链、一条 band 状态栏和各自独立的更新流程。任何一项都简单，但**合起来的记忆负担**足以让新用户放弃探索——记不住 `/ponytail-debt` 是干什么的，就不会用它。

帮助内容的传统去处是 README，但那对 AI agent 无效：**代理工作在对话上下文里，够不到浏览器**。用户在编辑器里问「ponytail 怎么用」，正确的应答位置是对话本身，而不是一条外链。

所以这不是「写份文档」能解决的问题，而是**帮助内容的可达性**问题：它必须住在代理能调用的地方。

> **设计立场**：它假设「自助发现是技能套件的采用瓶颈」——用户不会为了查一个命令切走上下文，于是查不到的命令等于不存在。

## 2. 核心设计决策

### 决策一：帮助即技能

**选了什么**：把速查卡做成可被对话调用的技能，与五个功能技能并列发布。

**为什么**：技能目录是代理唯一必然可达的内容面。帮助住进去之后，「怎么用」的问答链路变成一次技能调用——零上下文切换。同时 description 写明触发短语（「ponytail help」「怎么用 ponytail」），让模型在用户表达困惑时能自动调卡。

**备选方案**：只写 README，技能 description 里说「详见仓库」。**被否决的原因**：那把帮助变成了对代理不可达的资源，等于没有。

**代价**：卡片内容与真实行为可能脱节——它是一份手工同步的快照（见第 4 节）。

### 决策二：one-shot 纯展示

**选了什么**：与 ponytail-gain 措辞完全一致的边界——不改变模式、不写标记文件、不持久化。

**为什么**：帮助场景的高频变体是「用户只想看看有什么」。若调出帮助会改变会话状态（比如顺手激活 full 档），「随便看看」就变成了误操作入口。纯展示契约让 help 可以被放心地自动触发。

**代价**：无法从卡内直接执行动作（如「点了就切 lite」），切换必须由用户另发指令。

### 决策三：配置链写进卡片

**选了什么**：默认档位的修改方法（环境变量 > 配置文件 > `full` 的解析顺序、Windows 路径差异、`off` 的语义）直接写进技能正文。

**为什么**：配置是「想长期使用」的必经一步，也是文档最常缺位的一步。把解析链写死在卡里，卡片就从「命令目录」升级为「使用说明书」，自文档化且随技能分发。

**代价**：配置面的任何变动（新增配置项、改路径）都要同步卡片，维护点多了一处。

### 决策四：卡外问题指向仓库

**选了什么**：结尾给仓库 URL，注明「完整文档与示例」。

**为什么**：速查卡有硬性长度约束，塞不下示例与原理；诚实的做法是明确卡片的边界，把深度需求导流到完整文档，而不是把卡片写成压缩的 README。

**代价**：对离线/内网用户，这条 URL 不可达——恰好是本项目离线包场景要注意的点。

## 3. 机制如何运转

```
用户表达「怎么用 / 有什么命令 / ponytail help」
   ↓
description 匹配 → 调用 help 技能
   ↓
渲染速查卡：
  档位表 → 技能表（含跨宿主调用差异）→ 退出方式
  → band 用法 → 默认档位配置 → 更新流程 → 仓库链接
   ↓
状态零变化，结束
```

值得注意的结构选择是**技能表自我引用**（ponytail-help 也列在表里）与**档位表和主技能 description 的语义一致**——卡片与被描述者共享同一份措辞来源，降低了两处漂移的概率（但没有机制保证，仍靠手工同步）。

## 4. 什么时候会失效

| 场景 | 后果 | 原因 |
|------|------|------|
| 版本演进（改档位、加技能、挪配置） | 卡片过时，用户照旧卡操作失败 | 内容硬编码，无与行为同步的机制 |
| 离线 / 内网环境 | 「更多」链接不可达 | 深度文档只存在于 GitHub |
| 非 Claude Code / Codex 宿主 | 调用方式说明不覆盖，用户需自行摸索 | 卡片只列了两个宿主的调用差异 |
| 用户在卡内期待可执行动作 | 「点了没反应」的困惑 | one-shot 契约决定了卡片不可交互 |
| 长会话后用户忘记细节 | 需要再次调卡 | 卡片不持久化——这既是边界也是设计 |

## 5. 与其他技能的协作

| 关系 | 说明 |
|------|------|
| 是全家的目录 | 唯一同时描述其余五个技能的技能，新用户入口 |
| 与 ponytail-gain 同构 | 同为 one-shot 纯展示；措辞一致，可安全自动触发 |
| 服务主技能的档位体系 | 档位表是主技能 `argument-hint` 的展开说明 |
| 与 OpenSpec / superpowers 的对照 | 那两套用「总览文档」做入门（放在 docs/ 由人读），ponytail 用「帮助技能」做入门（放在对话里由代理读）——入口介质的选择本身是两种工作流哲学的缩影 |
