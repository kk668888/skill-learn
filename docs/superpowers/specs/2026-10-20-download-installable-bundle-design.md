# 可选安装的完整下载包设计

## 目标

查看器的单个下载入口提供可离线保存的完整资料包。用户解压后可以只阅读文档，也可以自行运行项目自带的安装脚本，将全部技能安装到 Claude Code；下载和解压本身不执行安装。

## 下载内容与交互

- 保留 `GET /api/download`，ZIP 根目录直接对应项目根目录，不再增加外层文件夹。
- 保留当前扫描范围内的全部 Markdown 原始字节；额外收入根级 `install-skills.mjs`，以及 `skills/` 下安装所需的全部普通文件，包括非 Markdown 脚本、资源、许可证与 `commands/` 文件。相同路径只归档一次。
- 排除隐藏目录、`node_modules`、符号链接和查看器自身文件。归档条目继续接受项目根边界与文件身份校验。
- 菜单动作改称“下载完整资料与技能包”，浏览器和响应头都使用 `skill-learn-bundle.zip`。搜索、目录过滤和当前文档不改变下载范围。
- 脚本仍以自身所在目录寻找同级 `skills/`；解压后可先运行 `node install-skills.mjs --list` 查看套件，再按脚本的 `--help` 选择安装范围和目标。脚本现有的 Claude Code 安装语义不改变。

## 服务端与部署

下载清单由现有 Markdown 扫描结果、完整技能源码树以及安装脚本路径合并、去重并排序。技能源码树只递归读取普通文件，跳过隐藏目录和依赖目录；不读取任意其他项目路径。现有 ZIP 流式输出、文件打开前后的校验、取消时关闭源流和失败时不提供完整下载的处理保持有效。

Docker 镜像在 `/app` 增加 `install-skills.mjs`，与已经复制的 `skills/` 同级。本机和容器因此使用相同归档规则。空的临时项目仍可返回空 ZIP；安装脚本与技能源码只存在其一时应在发送 ZIP 前报错，避免产生看似可安装但实际无法安装的包。

## 验证

- HTTP 下载测试核对脚本、非 Markdown 附属文件、OpenSpec 命令、原有 Markdown 及排除项的路径和字节；测试缺失脚本与符号链接等失败分支。
- 在临时目录解压真实仓库的 ZIP，运行 `node install-skills.mjs --list`，核对六套技能可被发现；不运行实际安装。
- 更新菜单和浏览器下载文件名测试，运行查看器全部测试、类型检查和构建，并校验相关 OpenSpec 规格。

## 取舍

一个完整包会比只含 Markdown 的包更大，并把技能附属程序一起分发；当前仓库技能源码约 3.4 MB，换取解压后可直接选择安装。只附安装脚本会因缺少非 Markdown 附属文件而不能完整安装；分成两个下载入口会增加界面选择与测试范围，因此本次维持单一入口。
