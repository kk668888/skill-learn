# markdown-document-upload Specification

## Purpose

定义本地查看器导入普通 Markdown 文档的用户行为：选择或创建分组、把文件可靠地保存到项目目录、处理冲突，并让新文档立即进入阅读与搜索流程。

## Requirements

### Requirement: 选择普通文档分组

查看器 SHALL 在上传单个 Markdown 文件时允许用户选择现有的普通文档分组，或输入名称创建一个新分组。可选的现有分组 MUST 包括“AI 文章”和已创建的普通文档分组；技能源码与技能文档目录 MUST NOT 成为上传目标。新分组 SHALL 与本次成功上传一起出现，不提供单独创建空分组的操作。

#### Scenario: 上传到 AI 文章

- **WHEN** 用户选择“AI 文章”并提交有效的 Markdown 文件
- **THEN** 文件保存到 `docs/ai-docs/`，原有文章路径不变

#### Scenario: 创建新分组并上传

- **WHEN** 用户输入尚不存在的有效分组名并提交有效的 Markdown 文件
- **THEN** 查看器在 `docs/collections/<分组名>/` 保存文件，并显示该分组及其文档

#### Scenario: 选择已有自建分组

- **WHEN** 用户选择此前创建的普通文档分组并提交有效文件
- **THEN** 新文件保存在该分组目录下，不创建同名的第二个分组

#### Scenario: 新分组名称已被使用

- **WHEN** 用户选择新建分组，但输入的名称与已有普通文档分组相同或仅大小写不同
- **THEN** 查看器提示选择已有分组或更换名称，不在该目录中写入文件

### Requirement: 校验上传输入

查看器 SHALL 只接受单个 UTF-8 编码的 `.md` 文件，文件大小不得超过 5 MiB。用户可在上传前修改目标文件名，但目标文件名 MUST 以 `.md` 结尾。文件名和新分组名 MUST 是安全的单级名称，不得为空、包含路径分隔符或路径穿越形式；无效输入 SHALL 显示明确原因，且 MUST NOT 写入文件或目录。

#### Scenario: 非 Markdown 文件或过大的文件

- **WHEN** 用户提交非 `.md` 文件、非 UTF-8 内容或超过 5 MiB 的文件
- **THEN** 查看器拒绝上传并说明原因，项目文档目录保持不变

#### Scenario: 非法目标名称

- **WHEN** 用户提交空白名称、路径分隔符、`.`、`..` 或其他不安全的文件名或新分组名
- **THEN** 查看器拒绝上传，文件不能写到允许的普通文档目录之外

### Requirement: 同名冲突不覆盖

同一分组中若已有与目标文件名相同的文件，查看器 MUST 返回冲突提示并保留已有文件原文，不得覆盖。冲突判断 MUST 避免因大小写差异在不同操作系统上产生意外覆盖；用户 SHALL 能修改目标文件名后重试，而无需重新选择源文件。

#### Scenario: 同名文件冲突

- **WHEN** 用户把 `笔记.md` 上传到已含 `笔记.md` 的分组
- **THEN** 查看器提示同名冲突，原文件内容保持不变，上传表单仍可修改文件名

#### Scenario: 仅大小写不同的文件名

- **WHEN** 分组已有 `Notes.md`，用户尝试保存为 `notes.md`
- **THEN** 查看器按同名冲突拒绝上传

### Requirement: 保存后立即可用

上传成功后，查看器 SHALL 无需整页刷新就更新目录树并打开新文档；该文件 SHALL 与普通文档一样可通过目录过滤、全文搜索和直接路径读取访问。保存失败时，查看器 MUST 给出错误反馈，不得显示成功状态或留下不完整的目标文件。

#### Scenario: 上传成功并阅读

- **WHEN** 用户完成一次有效上传
- **THEN** 新文档出现在所选分组，主阅读区打开其内容，随后进行的目录过滤和全文搜索能找到它

#### Scenario: 写入失败

- **WHEN** 目标目录不可写或保存过程中发生错误
- **THEN** 查看器显示保存失败，新文档不出现在目录树中，目标文件不保留不完整内容

### Requirement: 本地项目文件持久化

成功上传的文档 SHALL 作为项目目录内的 `.md` 文件保留，关闭并重新启动本地查看器后仍可浏览和搜索。上传操作 MUST NOT 自动执行 Git 暂存或提交。

#### Scenario: 重启后查看上传文档

- **WHEN** 用户上传文档后重启本地查看器
- **THEN** 文档仍出现在相同分组，内容与上传时一致
