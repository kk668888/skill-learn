## Context

参见 `proposal.md` 的动机。项目目前在 `AGENTS.md` 与 `CLAUDE.md` 两份工具入口中把技能文档限定为三类，且只为单技能生成中文版和详细设计讲解；套件级的原理文档偏重机制。`docs/skills/` 现有六个套件目录，其中 `anthropics` 暂无 `技能原理深度讲解.md`，其余五个目录已有该文件。新文档必须遵守现有目录归属、中文写作及不复制源码附属文件的约束。

## Goals / Non-Goals

**Goals:**

- 让第一次接触套件的读者按照一个真实可执行的案例完成第一步，知道自己应提供什么输入、会看到什么结果。
- 让快速入手与套件原理、逐段译文、单技能设计分析分别承担“怎么开始”“整体为什么”“原文说了什么”“单技能为什么”的职责。
- 让未来生成与更新快速入手时有明确触发方式和验收口径，避免普通对话误生成文件。
- 让查看器“浏览套件”的首次点击直接到达快速入手，且资料不完整的套件仍可打开现有文档。
- 让未设置阅读风格的读者默认看到“精致文章”，同时尊重已有选择。

**Non-Goals:**

- 不在本次补写 `anthropics` 缺失的套件原理文档；该篇快速入手只链接当前实际存在的相关文档。
- 不为每个技能单独创建快速入手，也不要求单篇教程覆盖套件的完整生命周期。
- 不在教程内运行案例、安装工具、生成代码或复制 `skills/` 中的运行文件。

## Decisions

### 1. 每套一篇，以任务案例组织

文件固定为 `docs/skills/<套件>/技能快速入手.md`。每篇只有一个主要入门案例，按“适用场景 → 准备条件 → 示例输入 → 操作步骤及可观察结果 → 完成判断 → 继续深入”组织。步骤可使用真实命令或对话提示，但须注明运行环境和副作用；对会修改项目的步骤，给出适合练习的隔离位置或示例项目。

选择任务案例而不是技能清单，是因为读者的首要问题是“第一步怎么做”。代价是每篇只展示一条入口路径，不能替代原理文档中对整套机制的说明。所有命令、技能名及预期产物须对照当前源码或 CLI 核实，示例不得把假想输出写成真实运行结果。

### 2. 套件案例按首个有意义的结果截断

建议案例方向如下；写作时以源码和现有文档校验具体触发语与产物：

| 套件 | 入门案例的完成点 |
|------|------------------|
| `anthropics` | 用 `skill-creator` 形成一个可检查的技能草稿或明确的创建流程 |
| `frontend-design-premium` | 在一个练习页面上完成一次设计方向确定及可观察的页面调整 |
| `grill` | 用一个小决策完成一次提问、回答与共识确认 |
| `impeccable` | 对一个练习界面完成一次诊断与有边界的改进 |
| `openspec` | 从一个小变更想法生成可审查的规划产物并查看状态 |
| `superpowers` | 从小需求完成一次澄清与设计确认，得到下一步计划入口 |

每个完成点应能被读者直接观察。需要用户选择或审批的环节，应写成明确的停点；不得暗示教程可以替用户作决定。

### 3. 更新文档规范及触发边界

在 `AGENTS.md` 与 `CLAUDE.md` 增列第四类文件，说明快速入手是套件级可跟做教程，不属于索引页或速查卡。增列明确的 `生成 <套件> 技能快速入手`、`更新 <套件> 技能快速入手` 触发短语；现有单技能触发仍只生成两份单技能文档。`生成 <套件> 全套技能文档` 覆盖该套件的快速入手以及所有单技能文档。同步更新两份文件的目录示意、分工表、完整动作和硬性约束中的“三类”表述，保留 Codex 与 Claude 各自的技能安装目录；把“套件原理是唯一的下钻入口”改为两篇套件级文档各自提供适当的后续链接。

选择显式触发而不是在任何提到“入手”的对话中自动生成，延续项目防误触发规则。代价是用户必须说出约定短语。

### 4. 链接只指向存在的文档，术语同步落表

快速入手的“继续深入”优先链接同套件原理文档及本案例涉及的技能中文版、详细设计讲解；目标不存在时不造空链接。`anthropics` 的套件原理文档缺口会在教程中如实处理，不顺带扩大本次写作范围。`CONTEXT.md` 增加“技能快速入手”的简洁定义和弃用称呼，防止其与“速查卡”混淆。

### 5. 欢迎页套件卡片选择首次阅读目标

查看器已把套件下的每篇 Markdown 收录为文件节点。欢迎页入口只需按套件文件路径找到 `docs/skills/<套件>/技能快速入手.md`，优先导航至它；若该文件不存在，再按既有逻辑打开套件原理文档、首个技能的中文版或源码、最后一个可读文件。这样无需改变树节点类型或侧边栏结构，且其他入口的导航行为不受影响。选择路径匹配而不是新增角色，是因为本次需求只改变欢迎页卡片的目标；若以后多个视图都需要区分快速入手，届时再提升为共享角色。

### 6. 默认阅读风格使用精致文章

将唯一的默认值 `DEFAULT_READING_THEME` 设为“精致文章”对应的 `editorial`。`readReadingTheme` 仍优先接受四种有效的已保存风格；无存储、空值、未知值或读取异常时才回退到该默认值。选择集中修改默认常量，是因为初始状态和异常降级已共享这一路径，避免在组件内加入另一套判断。代价是旧版本留下的未知值也会显示精致文章；保留有效旧选择则意味着部分老用户首次打开新版时仍看到原先的主题。

## Risks / Trade-offs

- [六套技能的触发方式不一致，套用同一命令模板会误导读者] → 统一章节职责，不统一具体操作；逐套核对源码和已有文档。
- [教程步骤依赖外部工具、模型或练习项目，读者无法复现] → 写清先决条件、可替代的练习环境、可观察的检查点和手动决策点。
- [新增第四类文档与现有“三类文件”“唯一入口”规则冲突] → 同步修订 `AGENTS.md` 和 `CLAUDE.md` 的所有相关表述，再生成教程。
- [套件原理文档可能与新版技能源码存在偏差] → 教程以实际技能源码为事实依据；发现偏差时记录为独立待办，不在本变更中暗改原理结论。
- [每套一篇无法覆盖全部技能] → 在结尾给出深入阅读路径，保持案例短而完整。
- [欢迎页跳转只在新文件存在时成立，旧目录或资料不全时可能没有目标] → 保留原有回退链，并以有无快速入手的套件树测试点击结果。
- [改动默认值可能覆盖既有阅读偏好] → 只改无有效偏好时的回退值，并测试四种有效保存值仍能恢复。

## Migration Plan

先更新两份项目文档规则和术语，再逐套编写六篇教程；随后调整欢迎页导航并验证回退，再将默认阅读风格设为精致文章；完成后检查目录中文件类型、链接目标、示例可执行性和每篇的结果检查点。文档与查看器改动可分别回退；无需数据迁移。
