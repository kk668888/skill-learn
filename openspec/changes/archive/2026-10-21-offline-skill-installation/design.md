## Context

见 [proposal.md](proposal.md) 与两份 delta spec。当前 `install-skills.mjs` 只向 `.claude/skills` 和 `.claude/commands` 复制仓库快照；`skills/` 内没有插件市场清单，OpenSpec 目录不含 CLI，Impeccable 目录不含目标平台引擎。查看器现有归档清单只接受 Markdown、根级安装脚本及 `skills/` 下的普通文件，并排除隐藏目录；下载接口与容器镜像都需要扩展，才能让同一个 ZIP 承载完整离线内容。

## Goals / Non-Goals

**Goals:**

- 将联网获取与断网安装分离，内网阶段只读取预先转入的本地文件。
- 让查看器的一次下载同时得到可阅读资料和清单列明组合所需的离线安装内容。
- 让安装策略与套件实际分发形态一致，并提供可核验、可重试的结果。
- 用断网环境验证安装和必要的首次运行路径。

**Non-Goals:**

- 不在离线包里分发 Claude Code、Codex、Node 或模型服务本体；缺少这些宿主前提时明确报错。
- 不把未声明支持、未完成断网验证的平台二进制塞入 ZIP，也不替上游发布新的官方插件。
- 不自动卸载或清理用户此前安装的插件与技能。

## Decisions

### 1. 预制内容并合并进现有 ZIP

新增外网制包入口，以固定版本清单锁定每套上游来源、目标工具、操作系统、架构和源文件校验值。它在项目根生成 `offline-kit/`：包级元数据、逐文件 SHA-256、来源与许可证，以及按工具和平台分开的插件市场、CLI、引擎和独立技能。这个目录是发布构建产物，不是手工维护的技能源码。制包先完成全部输入和依赖检查，再写入完成标记；缺件时不留下可下载的成功产物。

查看器沿用 `GET /api/download` 与 `skill-learn-bundle.zip`，把整个经校验的 `offline-kit/` 与既有资料、`skills/`、`install-skills.mjs` 放在同一个 ZIP 根目录，不增加外层目录。一个发布包可包含多个目标工具和平台组合，但仅在清单中列出实际具备完整依赖且已通过断网验收的组合。初次实施和端到端验证以当前 Windows x64 环境为基线；要扩展 Linux 或 macOS，先取得对应二进制并完成该平台验证。查看器不在下载请求中联网、执行制包或构建二进制。

归档清单增加对 `offline-kit/` 的受控扫描：只纳入完成清单列出的普通文件，允许该目录内的 `.claude-plugin`、`.agents` 和依赖目录，但拒绝符号链接、越界路径及未列入清单的文件。现有项目其他位置的隐藏项和 `node_modules` 继续排除。流式 ZIP、文件身份复核和取消时关闭源流的机制继续使用；下载前验证离线目录存在、完整且摘要匹配，失败时不发送成功 ZIP。容器镜像必须从发布构建上下文复制同一 `offline-kit/`，缺失则构建或下载失败。

### 2. 每套按真实形态准备 payload

| 套件 | `offline-kit/` 内容 | 内网动作 |
|---|---|---|
| Superpowers、grill | 对应宿主的完整上游插件目录，含 manifest、技能、hook、脚本和许可证 | 从包内本地市场安装插件 |
| frontend-design-premium | 对应宿主的自包含插件发行物，含匹配的 `frontend-design` | 从包内本地市场安装插件 |
| OpenSpec | 固定版本 CLI 及其完整可运行依赖 | 在指定项目运行包内 CLI 的初始化或更新 |
| Impeccable | 技能、安装器所需文件及目标平台引擎二进制 | 用包内引擎安装技能与项目 hook |
| Anthropic skill-creator | 完整技能目录及附属文件 | 安装为独立技能；不强制带入 Anthropic 其他示例技能 |

Claude Code 市场采用 `offline-kit/` 内 `.claude-plugin/marketplace.json` 和相对本地插件路径；Codex 市场采用同目录内 `.agents/plugins/marketplace.json` 及各插件的 Codex manifest。两种格式分别验证，不把 Claude 插件目录直接改名当成 Codex 插件。没有稳定的非交互本地安装入口时，适配器给出明确的本地 UI 步骤并保持该套为“待完成”，不能报告安装成功。

OpenSpec CLI 以包内路径调用，不进行全局 npm 安装；Impeccable 引擎放在启动器优先查找的同级平台目录，或显式传入包内引擎路径，禁止落入下载分支。两者的依赖闭包在制包与断网验证阶段确认。

### 3. 安装入口采用“检查 → 计划 → 执行 → 报告”

`install-skills.mjs` 默认从自身同级的 `offline-kit/` 读取离线内容，接收目标工具、项目路径、套件筛选和预览选项；可保留显式包目录覆盖供测试和受控部署使用。它先核对清单、平台、文件校验、宿主命令及已有插件／技能；所有选中套件的静态前提通过后才写入。每个套件由独立适配策略决定本地市场、项目 CLI 或文件安装，外部进程通过参数数组启动并继承交互终端，避免拼接 shell 字符串。

同名既有内容视为冲突：识别到本包同版本已安装时跳过，来源不明或同时存在插件与本地技能时不覆盖。执行中失败时停止后续套件，报告成功、失败和未执行项，供重新运行；不假称整个批次具备跨工具事务性。`--clean` 不再清理插件或来源不明的旧副本。

### 4. 验收必须真的断网

测试分三层：制包文件清单与哈希验证、从真实下载接口提取 ZIP 后在临时目录运行安装计划与冲突测试、无网络容器或隔离虚拟机中的真实安装和首次运行检查。测试至少覆盖六套的代表路径、OpenSpec 项目生成、Impeccable 引擎启动、插件 hook 装载，以及缺件、平台不匹配和重复安装。还要覆盖本机与容器下载内容一致、下载中断及缺件拒绝；只运行 `--list` 不构成离线可用性证明。

## Risks / Trade-offs

- **上游插件格式或 CLI 变化** → 固定版本和校验值，按宿主版本做本地安装验证；不支持的组合不发布。
- **现有 ZIP 变大且含可执行文件** → 只纳入清单声明并验收的组合，保留来源与许可证，沿用流式归档并逐文件核对；在界面说明包体和适用平台。
- **SHA-256 只能检验传输完整性，不能自行证明来源可信** → 制包时核对固定上游来源与输入摘要，内网分发走既有可信介质；不把哈希描述成数字签名。
- **插件管理器可能执行隐式更新检查** → 仅注册相对本地市场，并在网络封锁测试中确认目标版本的实际行为；无法保证离线的版本不标记为支持。
- **现有本地副本与新插件重复** → 安装前报告并跳过，不自动删除用户文件。

## Migration Plan

1. 保留 `--list` 供下载包查看套件；新安装入口默认读取同级 `offline-kit/`，缺少时明确报错，不继续默认打平安装六套。
2. 外网预制并验证首批工具／平台组合；发布构建将完整目录带入本机服务与容器镜像，查看器缺件时拒绝下载。
3. 更新查看器文案与下载规格，说明同一个 ZIP 同时包含资料与离线安装内容，并显示清单中的适用平台。
4. 旧安装不自动迁移。使用者检查重复项后可自行选择保留旧副本或手工移除，再重试本地插件安装。回滚时停用新市场或恢复旧版脚本；已存在文件仍由使用者管理。
