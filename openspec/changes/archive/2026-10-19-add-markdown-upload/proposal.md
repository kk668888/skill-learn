## Why

查看器目前只能读取项目中已有的 Markdown 文件。用户希望在本地运行查看器时直接上传普通文档，并把文件留在项目目录中，供后续阅读、搜索和 Git 管理。

## What Changes

- 增加单个 `.md` 文件上传入口，可选择已有普通文档分组，或在上传时创建新分组。
- 保留现有“AI 文章”分组及其 `docs/ai-docs/` 路径；自建分组的文件保存到 `docs/collections/<分组名>/`。
- 上传成功后刷新目录树并打开新文档；新文档参与现有的目录过滤和全文搜索。
- 对文件类型、文件名、分组名及上传大小作校验；同一分组遇到同名文件时提示冲突并要求改名，不覆盖已有内容。
- 上传仅面向普通文档，不写入 `docs/skills/` 或 `skills/`；不提供自动 Git 提交、独立创建空分组或生产部署上传能力。

## Capabilities

### New Capabilities

- `markdown-document-upload`：本地查看器上传普通 Markdown 文档、选择或创建分组、持久保存、冲突处理及上传后的阅读与搜索行为。

### Modified Capabilities

无。

## Impact

- 前端：查看器上传界面、API 客户端、目录树刷新与上传后导航。
- 后端：本地 Vite 服务中的 Express 写入接口、普通文档分组发现与目录树构建。
- 文件：现有 `docs/ai-docs/` 保持原位；新增的普通分组存放在 `docs/collections/`，文件作为普通项目文件由 Git 跟踪。
- 部署：当前范围是本地运行；未来 Docker 镜像若需要跨容器重建保留文件，应将文档目录挂载为持久卷。
