## Context

动机和范围见 [proposal.md](proposal.md)。视觉依据见 [四种阅读主题原型](assets/reading-theme-prototypes.png)。原型只约定阅读风格，不要求复制图中的示例文章、阅读时间或品牌工具栏。

现有 `useTheme.ts` 使用 `viewer-theme` 保存 light/dark，通过根节点 `data-theme` 控制全站 CSS 变量。`styles.css` 混合了应用布局、Markdown 排版和暗色代码高亮；`MarkdownBody.tsx` 另行导入 GitHub 浅色高亮样式。`DocView` 渲染文档头、进度条与正文，`App` 的主区域承担滚动，侧栏与大纲为同级区域。

本变更跨状态、视图与样式模块，且必须处理全局主题与局部代码背景的优先级，因此需要此设计文档。

## Goals / Non-Goals

**Goals:**

- 让阅读风格具备单一配置入口和独立偏好状态，沿用现有组件和阅读数据流。
- 用局部 CSS 变量管理风格，减少对布局和操作行为的影响。
- 为四种风格与两种明暗组合定义明确的验证范围。

**Non-Goals:**

- 不引入外部主题库、任意 CSS 执行能力、服务器偏好存储或在线字体依赖。
- 不更换 Markdown 渲染器，不重新设计侧边栏、欢迎页和大纲。
- 不增加字号、行距等独立设置；本轮由四种预设统一控制。

## Decisions

### 1. 阅读风格采用独立状态

新增 `viewer/src/lib/readingTheme.ts` 集中定义稳定 ID、中文名称、默认值和保存值校验：`classic`（经典文档）、`paper`（纸张阅读）、`minimal`（简洁笔记）、`editorial`（精致文章）。新增 `useReadingTheme`，使用独立存储键 `viewer-reading-theme`，由 App 持有并跨文档复用。读取无效值回退 classic，读写异常只影响持久化，不能影响当前会话状态。

现有 `useTheme` 和 `viewer-theme` 保持明暗控制职责。备选是把风格与明暗合成八个主题 ID，但这会重写已有偏好并让用户每次切换风格时重复决定明暗；独立状态更适合当前界面。

### 2. 使用原生选择控件即时应用

在文档头放置带明确 label 的原生 select，显示四个中文名称和当前选项。选择即预览、即保存，不增加应用按钮或悬停预览。控件在窄屏换行，使用现有焦点样式。

备选是带缩略图的浮层选择器，可增强发现性，但引入焦点管理和更多占用空间。第一版四个选项使用原生控件即可。控件更新仅更改样式状态，避免重新挂载文档、重取正文或调用滚动复位逻辑；字体变化引起的自然重排可以发生，不承诺像素级滚动位置不变。

### 3. 风格限定于打开文档的主区域

文档打开时在 `.main` 上设置 `data-reading-theme`，使阅读区底色覆盖完整可视区域；无文档时移除该属性，欢迎页继续使用全局配色。标签向下作用于文档头和正文，侧边栏、大纲不在该作用域内。

新增 `viewer/src/reading-themes.css`，由应用样式入口加载。定义局部 `--reading-*` 排版变量，以及局部覆盖现有颜色变量；经典文档为基础，再按风格、明暗组合覆盖。全局明暗选择器与局部风格选择器组合，不改全站根变量的值。保留布局尺寸、滚动容器与移动端规则。

备选是给每套风格复制整份 CSS，容易让复制按钮、表格溢出和响应式修复发生漂移。共享结构规则加局部变量成本较低；只有标题边线、引用装饰等结构差异使用风格选择器。

### 4. 原型转化为可维护的风格约束

| ID | 浅色方向 | 字体和排版 | 深色适配原则 |
|---|---|---|---|
| classic | 白底、蓝色强调、灰色代码块 | 系统无衬线，清晰标题边线，紧凑表格 | 接近现有 GitHub 暗色效果 |
| paper | 米白底、棕色文字、赭色强调 | 本地宋体／衬线回退，正文行距较舒展 | 暖炭色底、浅暖色文字，保留纸张的字体节奏 |
| minimal | 淡灰白底、绿色强调 | 无衬线，简化标题边线，细线引用，以横线分隔表格 | 中性深灰底、柔和绿色，保持低装饰 |
| editorial | 近白暖底、暗红强调、深色代码块 | 衬线大标题、无衬线正文、强调小节与引号 | 深暖灰底、浅色标题、柔和红色强调，代码块继续独立深色 |

中文衬线字体采用本地字体栈（如 Songti SC、SimSun、Noto Serif CJK SC、serif），不发起字体下载。原型是方向参考；实际字号、留白和颜色在真实中文文档上校准，满足规格中的可读性与对比度要求。

### 5. 代码高亮统一进入阅读样式作用域

整理 `MarkdownBody.tsx` 的浅色主题导入和 `styles.css` 的根级暗色覆盖，使用阅读主题定义的代码背景及 token 变量统一控制 `.hljs`。精致文章在浅色模式中也使用深色代码底色，因此高亮配色必须按代码块背景决定，不能仅检查全局 dark。

覆盖现有常见 token 类型和 diff 增删颜色，同时适配工具栏、复制反馈和行内代码。保持 rehype-highlight 的输出结构与 CodeBlock 复制逻辑。备选是按风格切换整套第三方 CSS，加载顺序及全局选择器容易覆盖正文局部风格，故本轮不采用。

## Risks / Trade-offs

- [旧暗色选择器优先级压过局部风格] → 集中整理 Markdown 和高亮规则，检查四种风格 × 两种明暗组合，避免依赖任意加载顺序。
- [不同系统的中文衬线字体宽度差异] → 使用本地回退栈和流式布局，验收实际文字可读、无裁切，不要求像素复刻图片。
- [字体和间距变化导致文档重排] → 不重挂载文档或重置滚动；允许自然重排并检查阅读进度仍正确反映当前位置。
- [视觉装饰降低长文或代码可读性] → 用同一篇包含多级标题、列表、引用、宽表格和多语言代码的真实文档对照；检查普通文本及高亮 token 的对比度。
- [存储被禁用或旧值失效] → 明确默认值与异常降级，并测试同会话跨文档保留选择。

## Migration Plan

1. 新增阅读风格状态与局部样式，已有明暗偏好继续生效；没有新偏好时进入经典文档。
2. 运行偏好状态相关测试、原有测试及类型检查。
3. 浏览器检查桌面和 390px 窄屏，覆盖四种风格的两种明暗模式；验证切换、刷新、键盘选择、复制、链接及锚点行为。
4. 回退时移除新增入口、状态和样式；新的存储键即使留在浏览器中也不影响旧版，已有 `viewer-theme` 无需迁移。
